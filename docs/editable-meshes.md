# Editable Mesh source and cooked projection

`.mesh.json` is a version-1 `forge.editable-mesh` document with one persistent Mesh `asset_id`, `next_id`, `vertices` with stable IDs and XYZ positions, and `faces` with stable IDs and ordered corners. Each corner names a vertex ID and owns a two-component UV. The source is authored data; it is not loaded by gameplay. Unknown versions reject explicitly; there is no implicit conversion of imported Model subassets.

`AssetSourceDocument` owns candidate-before-commit edits, a revision check, source save and independent Undo/Redo. Its checkpoints are bounded to 64 entries and 8 MiB per history direction; source JSON is capped at 2 MiB. A tool changes one candidate, validates it, then creates one history entry. Element IDs are never reused. Extrusion replaces the selected face with a new cap ID and new side-wall IDs; the editor selects the cap. A rejected edit changes neither source nor history. This small source format avoids a second asset/scene ownership system.

Validation admits at most 4,096 vertices, 4,096 faces and 16,384 face corners; each face has 3–16 strictly convex, planar corners. Vertices referenced by a face must exist and be unique within it; shared edges may have at most two uses with opposite winding. Coordinates must be finite and within the source bounds. These checks are the supported first modeling slice, not a general polygon repair or automatic unwrap system.

The `forge.mesh.editable` trusted CPU importer triangulates face fans into the existing immutable `MeshData` format, with POSITION, face NORMAL and independent TEXCOORD_0 streams. It publishes `mesh.bin` through the existing candidate/cache/catalog selection pipeline as a root Mesh asset. A failed candidate leaves the last good selected revision. The existing Mesh resource pool and Mesh Renderer load that root Mesh; scene instance transforms and material bindings retain their existing owners. Runtime packaging validates the selected cooked artifact and strips the authored `.mesh.json` source. Desktop Windows D3D12 and Linux CPU cook targets share the source schema; no new runtime ABI or editor code is shipped with a standalone game.

Texture UV origin is top left. Planar projection is deterministic and uses the dominant face-normal axis; it does not claim island packing, distortion control or automatic unwrap. Source edits and preview are bounded to the supported small-mesh profile. Larger sculpting, painting and modifier workflows need separate bulk storage and evaluation design.
