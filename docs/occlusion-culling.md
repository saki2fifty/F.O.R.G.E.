# Current-view hierarchical occlusion culling

`rendering.occlusion_culling` is an optional Scene rendering-version-1 object:

```json
{"enabled": false, "depth_bias": 0.0001}
```

`enabled` is strictly boolean. Bias is finite normalized depth from 0 to 0.01;
source checks precede float narrowing. Native typed consumers share validation.
Older Scene reads do not materialize defaults. Existing Scene patch/history,
reference inspection, automation discovery, MCP and runtime packaging own the
authoring workflow. Unknown source extensions retain the ordinary opaque-metadata
inspection policy. No entities or authoring identities are generated by rendering.

## Existing owners

MeshSceneRenderer owns eligibility, sorting and compatible adjacent batches. One
batch-boundary evaluator serves query preparation and the existing draw loop.
MeshDrawBundle borrows its existing built-in depth role for eligible individual
occluders; MeshDraw submits the same selected geometry through direct or GPU
indirect arguments. Surface-effect MRT routing remains separate from indirect
draw submission.

The private MeshOcclusion facet owns derived GPU scratch only: a reusable D32
occluder target, a structured far-depth hierarchy, bounded query/argument buffers,
three compute pipelines and their parameters. It owns no scene/resource registry,
visibility database, authored flags or readback. Existing device retirement governs
native resources.

## Conservative current-view profile

Only built-in opaque, depth-tested/writing triangle Mesh parts without skin,
morph targets or wind enter this profile. Object transforms may animate. Custom
surfaces, transmission, masked/blended parts and other geometry scopes keep direct
submission. Their shadow, picking and ordinary layer/visibility owners remain
unchanged.

RenderBounds encloses actual binary32 world rows, camera-relative translation,
camera basis and projection. Outward dot-product error covers fused/separate
arithmetic; subnormal coefficients that can flush before multiplication decline.
Eight camera-space interval corners retain perspective correlation. Conservative
pixel edges include a full rasterization pixel; nearest depth rounds toward zero.
Nonfinite/overflow/uncertain eye, near or far crossings keep direct submission.
Every batch unions member rectangles and selects the minimum member depth. An
uncertain member keeps the entire batch direct.

Up to 32 useful cheap occluder parts write separate current-view depth. They need
at most 8192 submitted elements and a projected bounding rectangle covering at
least 1/64 of the view. Selection ranks rectangle area per submitted element.
The exact effective camera, including temporal jitter, projects these parts and
their queries. Main depth is untouched; existing targets are restored before
temporal/MRT/current-layer drawing.

The hierarchy starts with conservative 2x2 maxima and power-of-two padding, then
reduces to a full tail. Missing/invalid depth is far depth 1. Dispatches write
disjoint structured-buffer regions with explicit UAV barriers. Query compute
samples a conservative covering level, rejecting only when the nearest bound is
strictly farther than all covered depth plus bias. It zeros only NumInstances in
an otherwise original draw command. Final UAV-to-indirect transition precedes
ordinary ordered submissions. Indexed commands use five 32-bit words; nonindexed
draws use the first four at the same 20-byte command stride.

Each camera builds fresh depth and masks. Declines and failures cannot expose a
previous mask. A rejected instanced submission falls back through the existing
individual direct-draw recovery path. No production CPU visibility readback,
previous-frame depth, entity deletion or visibility-component mutation occurs.

## Storage and supported device profile

Compute shaders and basic indirect drawing are required. Multiple-command and
counter-buffer features are unnecessary. The full source target is bounded by
8,388,608 pixels, 16384 pixels per axis, actual device limits, and 64 MiB logical
depth-plus-hierarchy storage. A 3840x2160 target uses 33,177,600 depth bytes and
22,369,620 hierarchy bytes. Subviewports use local query coordinates and source
offsets. Up to 4096 queries add 131,072 bytes, indirect commands add 81,920 bytes,
and parameters add 64 bytes. Resources grow/reuse and may stay cached while
disabled. Temporary resize overlap and native in-flight retirement are separate
from the logical storage allowance.

Larger views, unsupported capability or uncertain geometry retain ordinary draws.
Preparation failures report a warning and restore camera targets. CPU DrawStats
report submitted occluders, queries and indirect calls; they do not claim a hidden
object count. A zero-instance GPU command still entails its CPU submission and
binding work. Open scenes can incur extra work without useful rejection.

## Validation scope

Focused tests cover independent hierarchy footprints and GPU-float point oracles,
4096 query/attribute limits, native indexed/nonindexed draws, current/invalid/
subviewport depth, and reference-pixel motion/material/deformation cases.
Test-only pipeline statistics establish actual suppressed vertex work in a dense
occluded workload. Serialized software Vulkan timing is specific to that workload
and backend; it is not physical GPU performance acceptance. Gallery169 exercises
moving rigid occluders and source-hidden relocated game content. Windows and
physical hardware acceptance remain separately queued.
